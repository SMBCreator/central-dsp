## 6.5 Деньги  `V`

Кто списывает фактическую цену и идемпотентность — в `backend/routers/rtb.py` (`/win`) — **не проверено в этом проходе**, обязательный пункт ниже.

После `/cron/reset-daily` (00:00 UTC) — снова биддит. *При провале:* проверить ключи и TTL в `ReserveBudget`.

## 6.8 Нагрузка и деградация  `V`

Инструмент: `backend/loadtest/rtb_load.py --url --token --qps --seconds --concurrency --p99-budget-ms --warmup-seconds` (`rtb_load.py:66-72`). Результаты сохранять в `docs/audit/loadtest/<дата>-<сценарий>.md` (решение из MEMORY).

- [ ] **Базовая нагрузка на Go.** `--qps 35000 --concurrency 400 --seconds 120 --p99-budget-ms 30` с машины в той же сети. *Критерий:* достигнуто ≥ 35k QPS фактических, p99 ≤ 30 мс, 0 ответов 5xx, доля 200 стабильна. *При провале:* сначала исключить генератор (Python asyncio может не выдать 35k — тогда запускать 2–3 процесса или `wrk`/`vegeta`), затем `/metrics` Go: `bid_latency_seconds`, `redis_latency`, GC.
- [ ] **Redis down 30 с.** Под нагрузкой 5k QPS `docker compose stop redis; sleep 30; docker compose start redis`. *Критерий:* биддер отвечает (QPS-гейт fail-open, `handler.go:144`); метрика `gate_error` растёт; **бюджетный гейт** — ожидание «fail-close там, где деньги»: биддер должен отвечать 204 при ошибке `GateAndReserve`, **не проверено** — прочитать обработку ошибки в `handler.go` около вызова `GateAndReserve`; после восстановления `gate_error` перестаёт расти, 200 возвращаются. Алерт `BidderRedisDown` сработал (`alerts.yml:26`). *При провале (биддит без резерва):* критично — перерасход бюджета; фикс: при ошибке резерва → no-bid.
- [ ] **Postgres down.** `docker compose stop postgres` на 60 с. *Критерий:* Go продолжает торговать на последнем снимке фида (алерт `BidderFeedStale` через порог, `alerts.yml:14`); бэкенд: GET могут отдавать кэш/503, любой POST/PATCH → 503 с JSON `detail`, без трейсбека; фронт показывает баннер ошибки, не белый экран (проверить `frontend` обработку 503 в `lib/api.ts`). *При провале:* глобальный exception handler в FastAPI для `asyncpg` ошибок → 503.
- [ ] **Бэкенд под нагрузкой UI.** 50 параллельных `GET /stats/summary` + `/stats/breakdown` за 30 дней. *Критерий:* p95 < 1 с, нет таймаутов nginx (`proxy_read_timeout 300s`, DEPLOYMENT:153).

## 6.9 Безопасность  `V` + `S` (код)

- [ ] **Заголовки фронта.** Уже в `frontend/next.config.*`: HSTS `max-age=63072000`, `X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy-Report-Only` (`next.config:31-41`). *Как:* `curl -sI https://<host>/ | grep -iE 'strict-transport|x-frame|content-security|x-content-type|referrer'`. *Критерий:* все присутствуют; через 2 недели без нарушений в консоли — переключить на enforcing `Content-Security-Policy` (`connect-src` должен включать API-домен).
- [ ] **nginx.** *Как:* прочитать боевой `nginx.conf` на VPS (в репозитории конфига нет — только описание в `docs/DEPLOYMENT.md:153`). *Критерий:* `client_max_body_size` — 60m только для `/api/` upload-ручек, для `/rtb/` — ≤ 512k; `limit_req` на `/api/auth/` и `/pixel/`; `location ~ ^/(internal|cron)/` — `allow 127.0.0.1; deny all;` или проверка Bearer `CRON_SECRET` (в коде: `cron.py:19` защищён только если `CRON_SECRET` задан — при пустом значении ручки **открыты**). *При провале:* закрыть в nginx, задать `CRON_SECRET`.
- [ ] **Секреты не в git.** `git log -p --all | grep -iE '(secret|password|token)\s*[:=]\s*["'\''][A-Za-z0-9+/=]{16,}' | head` — пусто; `.env` в `.gitignore`. *При провале:* ротация секрета + `git filter-repo` по согласованию.
- [ ] **Токены SSP — только хэши.** После 032: `SELECT auth_token FROM supply_partners` → колонки нет / NULL; `auth_token_hash` заполнен; `rotate-token` возвращает plaintext один раз (`supply_partners.py`), в логах nginx/бэкенда plaintext не встречается (`grep -r csp_ /var/log/`).
- [ ] **CORS.** `main.py` `CORSMiddleware` — `allow_origins` не `*`, только домены кабинета. *Как:* `curl -H 'Origin: https://evil.example' -I /api/auth/me` → нет `Access-Control-Allow-Origin`. Исключение — `/pixel/collect` отдаёт `*` намеренно (`pixel.py:204`).
- [ ] **Логи без PII/токенов.** 10 минут прода → `grep -E 'cdsp_session=|X-CentralDSP-Token|csp_[a-z0-9]{20}|@[a-z]+\.[a-z]{2,}' /var/log/nginx/*.log backend.log` пусто. *При провале:* маскирование в access_log (`map`), в бэкенде — не логировать заголовки.

## 6.11 Предсказание проблем на выпуске и митигации

| Риск | Почему вероятен именно у нас | Как заметить | Митигация (до выпуска / при инциденте) |
|------|------------------------------|--------------|----------------------------------------|
| Расхождение сумм с отчётами SSP из-за часовых поясов | SSP отчитываются по МСК, у нас всё UTC (решение зафиксировано) | Расхождение ровно на 3-часовой сдвиг при сверке по дням | Сверку делать по UTC-часам, в отчётах для партнёров добавить колонку `hour_msk`; в UI метка «время UTC» уже есть |
| SSP присылает нестандартные поля (`imp.ext.*`, `bcat`, `badv`, `user.eids` расширения) | Каждый SSP имеет свой диалект OpenRTB 2.5/2.6 | Рост `nobid_reason_parse`/5xx на конкретном `endpoint_key` | Парсер Go должен игнорировать неизвестные поля (проверить, что структуры без `DisallowUnknownFields`), логировать первые N неизвестных ключей per-partner в debug, не падать |
| Низкий win-rate из-за `bidfloor` в другой валюте | `RTB_CURRENCY` фиксирован, SSP может слать `cur: ["USD"]` и floor в USD | `BidderWinGapAnomaly`, win-rate < 5 % у одного партнёра при нормальном у других | Сравнивать `cur` запроса с `RTB_CURRENCY`; при несовпадении — конвертировать floor по курсу из `/cron/fx-refresh` или no-bid с причиной `currency_mismatch` |
| Клик-трекер без `Referer` (редирект, in-app, privacy-браузеры) помечается как фрод | Антифрод-эвристики часто требуют Referer | Падение CTR при росте кликов в bid_events с `fraud_reason=no_referer` | Отсутствие Referer — не признак фрода само по себе; учитывать только в сочетании с другими сигналами |
| Частотный кап по IP режет пользователей за NAT (мобильные операторы, офисы) | Один IP = тысячи людей | Резкое падение показов у мобильного трафика, cap срабатывает с первого запроса | Ключ капа — `user.id`/`device.ifa`, IP только как fallback без ifa и с большим лимитом (проверить в `GateAndReserve` какой ключ используется — 6.5) |
| Партиции `bid_events` не созданы (cron не отработал, VPS перезагружался) | Записи молча падают в DEFAULT-партицию, запросы замедляются | `rows_in_default_partition > 0` в `/cron/retention` | Создавать партиции на +7 дней (уже `ensure_partitions(current_date, +7)`), алерт из D8, ручной `SELECT bid_events_ensure_partitions(...)` в runbook |
| Партнёр ротирует токен «в лоб» | После 032 сверка по хэшу; новый токен активен мгновенно, старый — нет → 403 у всех запросов партнёра до обновления на его стороне | `EventTokenRejectsSpike` / всплеск 403 на `/rtb/bid/<key>` | Grace-период: хранить `auth_token_hash` и `auth_token_hash_prev` с `prev_valid_until` (24 ч), принимать оба; миграция 034 (по согласованию) |
| HTML5-креатив с внешним `<script>` ломает CSP площадки | Площадки всё чаще ставят строгий CSP | Жалобы SSP, показы без кликов на конкретных доменах | Модерация HTML5 (GAP-030): запрет внешних скриптов вне whitelist, проверка при загрузке |
| Рост памяти Redis от ключей дедупа пикселя/капов | Ключи per-event/per-user без TTL или с большим TTL | `redis-cli INFO memory`, `used_memory` растёт линейно, eviction | Проверить TTL у `pixel:dedup:*`, `cap:*`, `win:*` (`redis-cli --scan --pattern 'pixel:*' \| head; TTL <key>`); `maxmemory-policy volatile-ttl` |
| `pnpm build` на VPS с другой версией Node | Локально/в v0 — Node 22, на VPS может быть 18/20 | Ошибки сборки Next 16 / другие хэши бандла | `.nvmrc` = 22 + `engines.node` в `frontend/package.json` (D9); сборка только в Docker `node:22-alpine` |
| Python-биддер случайно включён параллельно Go | `RTB_PYTHON_SERVING` в `.env` | Двойные биды на один request id, двойное списание | В проде `RTB_PYTHON_SERVING=0`, nginx маршрутизирует `/rtb/` только на Go; проверка в 6.1 |
| `CRON_SECRET` пустой → cron-ручки открыты | Защита включается только если переменная задана (`cron.py:19`) | Любой снаружи может вызвать `/cron/reset-daily` и обнулить дневные расходы | Fail-fast при пустом `CRON_SECRET` в production; nginx `deny all` на `/cron/` кроме localhost |
